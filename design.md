## Mission

Create a new Go project called **nomctl** — a single-binary CLI/TUI for deploying and operating Zenon Network (NoM) nodes. This is a port of the bash toolkit at https://github.com/hypercore-one/deployment (clone it locally as a reference before writing any code). Feature parity with the existing scripts is the goal for v0.1.0 — do not add new features (no orchestrator management, no log push, no diagnostics) in this phase.

## Hard requirements

1. **Remove HyperQube entirely.** The bash version supports two node types: `zenon` and `hyperqube`. HyperQube is dead. Strip every reference to `hyperqube`, `hqzd`, `hqz`, `ZNNSH_HQZD_*`, the HyperQube genesis URL, and the `[zenon|hyperqube]` argument pattern. There is exactly one node type. No `--node-type` flag, no abstraction layer "in case we support other chains later." Grep the reference repo for `hq` and `hyperqube` case-insensitively and confirm none of those code paths survive the port.
2. **Single static binary.** Pure Go, CGO_ENABLED=0, targets `linux/amd64` and `linux/arm64`. No runtime dependency on gum, jq, or any apt package beyond what the deploy flow itself installs.
3. **Go 1.23+, module path** `github.com/hypercore-one/nomctl` (make the module path a variable I can change easily if it lands elsewhere).
4. **License: GPL-3.0.** The source project is GPL-3.0 and this is a derivative work.

## Feature parity checklist (port from the bash `lib/` scripts)

| Bash source | nomctl command | Notes |
|---|---|---|
| `deploy.sh`, `build.sh` | `nomctl deploy [--repo URL] [--branch NAME]` | Install Go toolchain if missing, clone go-zenon, build `znnd`, install to `/usr/local/bin`, create + enable the `go-zenon` systemd unit |
| `backup.sh` | `nomctl backup [--max-backups N] [--cadence DAYS] [--hour HOUR]` | Snapshot `/root/.znn` to `/backup`, retention pruning, scheduled backups (systemd timer, not cron) |
| `restore.sh` | `nomctl restore [--file FILE]` | Interactive picker when `--file` omitted |
| `start.sh` / `stop.sh` / `restart.sh` | `nomctl start` / `stop` / `restart` | systemd service control |
| `monitor.sh` | `nomctl logs [-f]` | Follow journald output for the service |
| `resync.sh` | `nomctl resync` | Stop service, wipe chain data (preserve wallet/keystore and config), restart from genesis |
| `analytics.sh`, `grafana.sh`, `dashboards/` | `nomctl analytics install` | Prometheus + node_exporter + Grafana stack; embed the dashboard JSON files in the binary via `embed.FS` |
| `menu.sh` | `nomctl` (no args) | Interactive TUI covering all of the above |
| `help.sh` | `nomctl --help` | Generated by the CLI framework |

Read each bash script carefully and preserve its actual behavior (paths, service names, safety checks like the 15 GB free-space minimum) unless it exists only for HyperQube support.

## Architecture

- **CLI:** `spf13/cobra`. Every TUI action must also be reachable non-interactively for automation, exactly like the bash version.
- **TUI:** Charm stack — `bubbletea` + `huh` + `lipgloss`. The bash version uses gum, which is Charm's CLI wrapper, so the look and feel should carry over naturally.
- **Config:** environment variables with a `NOMCTL_` prefix replacing the old `ZNNSH_` prefix (e.g. `NOMCTL_REPO_URL`, `NOMCTL_BRANCH_NAME`, `NOMCTL_ZNN_DIR`, `NOMCTL_BACKUP_DIR`). Same defaults as `lib/config.sh` minus everything HyperQube. Flags override env vars. Centralize in one `internal/config` package.
- **systemd:** shell out to `systemctl`/`journalctl` via `os/exec` (do not pull in dbus bindings for v0.1). Wrap all external command execution in one `internal/execx` helper that logs commands in debug mode.
- **Privileges:** most commands need root; check EUID at startup for commands that require it and fail with a clear message instead of failing mid-operation.
- **Logging:** `log/slog`, human-friendly console handler, `--debug` flag mirrors `ZNNSH_DEBUG`.

## Release hosting

- **goreleaser** config producing `linux/amd64` and `linux/arm64` archives plus a `checksums.txt`, published to GitHub Releases on tag push via a GitHub Actions workflow.
- `install.sh` is the one-liner entry point for operators (`curl -fsSL .../install.sh | sudo bash`): detects arch, downloads the latest release, verifies the checksum, installs the binary. Keep it short and readable — it is the only shell script left in the project.
- README must document: quick start (install.sh and `go install` paths), every subcommand, every `NOMCTL_*` variable with defaults, and requirements (Debian/Ubuntu, root, amd64/arm64).

## Working style

- Work in phases and commit after each: (1) scaffold + config + execx, (2) service control + logs, (3) deploy/build, (4) backup/restore/resync, (5) analytics + embedded dashboards, (6) TUI, (7) goreleaser + CI + install.sh + README.
- Unit-test what's testable without root (config parsing, backup retention logic, arg handling). Gate anything needing root/systemd behind a build tag or skip when not root.
- `gofmt`, `go vet`, and `golangci-lint run` must pass. Add a `make lint` target.
- At the end, print a summary of every behavioral difference from the bash version, however small.

## Acceptance criteria

- `go build ./...` produces a working static binary on both target architectures.
- `nomctl --help` shows all subcommands; `nomctl` with no args launches the TUI.
- `grep -ri "hyperqube\|hqzd\|hqz" .` returns nothing outside the git history.
- A fresh Ubuntu 24.04 box can go from `install.sh` to a syncing node using only `nomctl deploy` and `nomctl start`.
