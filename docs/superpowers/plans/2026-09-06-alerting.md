# Alerting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Telegram alerts for node operators through a shared relay: `nomctl alerts` on the node evaluates rules over metrics samples and pushes state changes to `nomctl-relay`, which forwards them to the paired Telegram chat.

**Architecture:** `internal/alertproto` holds the wire types and HMAC signing shared by both sides. `internal/alerts` is the node side: config file, pure rules over a sample history, a daemon loop, and the relay client. `internal/relay` is the server: a `Store` interface with in-memory and SQLite implementations, HTTP handlers, delivery rules, the node-silent ticker, and a Telegram Bot API client with long polling. `cmd/nomctl-relay` is the second binary, shipped as a container.

**Tech Stack:** Go 1.24, net/http, crypto/hmac, `modernc.org/sqlite` (pure Go), cobra, existing `internal/metrics` sampler. No other new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-06-alerting-design.md`

## Global Constraints

- Module `github.com/0x3639/nomctl`; run go with `GOWORK=off`; `make lint` (gofmt, vet, golangci-lint) must pass after every task; `CGO_ENABLED=0` must still build both binaries for linux/amd64 and linux/arm64.
- Bot token exists only in the relay's environment. Node secrets are never logged.
- Node requests are signed: headers `X-Nomctl-Node`, `X-Nomctl-Timestamp`, `X-Nomctl-Signature` = hex HMAC-SHA256(secret, timestamp + "\n" + body); 5 minute replay window.
- Alert names, severities and default thresholds exactly as the spec table.

### Task 3: Rules

**Files:** Create `internal/alerts/rules.go`, test `internal/alerts/rules_test.go`.

**Produces:**
```go
type Result struct { Firing bool; Detail string }
type Rule interface { Name() string; Evaluate(history []metrics.Sample, cfg RuleConfig) Result }
func AllRules() []Rule
const HistoryWindow = 30 * time.Minute
func trimHistory(h []metrics.Sample, now time.Time) []metrics.Sample
func lastN(h []metrics.Sample, n int) []metrics.Sample
func since(h []metrics.Sample, d time.Duration) []metrics.Sample // samples within the last d
```
Rules (newest sample last):
- `service_down`: last 2 samples exist and both `Service.ActiveState != "active"` (a found unit). Detail: "go-zenon inactive (dead), 3 restarts".
- `crash_loop`: within `window_minutes`, NRestarts increased by >= `count` between first and last sample.
- `sync_stalled`: last 2 samples `Node.Reachable && Node.Stalled`.
- `sync_behind`: samples within `minutes` all reachable and syncing, at least 2, and `(target-current)` of last >= that of first.
- `not_enough_peers`: every sample within `minutes` (need coverage >= minutes - interval) reachable and (`State == NotEnoughPeers` or `NumPeers < min_peers`).
- `disk_low`: last sample `Host.DataDirTotal > 0 && DataDirFree < min_free_gb GiB`.
- `memory_high`: last sample process present and `RSS > pct/100 * MemTotal`.
- `fds_high`: last sample present, FDLimit > 0, `OpenFDs > pct/100 * FDLimit`.
- `rpc_unreachable`: all samples within `minutes` have service active and `!Node.Reachable`.
- `backup_stale`: evaluated from a `BackupInfo` injected on the sample history's last element via a package-level `backupChecker func() (enabled bool, newest time.Time, cadenceDays int)` (the daemon sets it; tests stub it). Fires when enabled and `now - newest > (cadence+1) days`.

- [ ] Tests: for each rule a table with (history builder, cfg) → firing/not, including hysteresis cases (single bad sample does not fire `service_down`; recovery). Helper `mk(t time.Time, mut func(*metrics.Sample))` builds samples from a healthy base.
- [ ] Implement.
- [ ] Test + lint; commit "Add alert rules".

`Step`: sample → append/trim history → evaluate enabled rules → for each: transition to firing sends `firing` (Title from `alertproto.Lookup`, Detail from rule), transition to ok sends `ok`, still firing and `now - LastSent >= 10m` sends `firing` again; first Step after start never sends transitions but sends one `info` "alerts started"; heartbeat every step with Summary from the sample; on 401 set `Unpaired`, stop sending; on other errors set `LastError`; write state file (0600, atomic) every step.

### Task 7: Relay server: handlers, delivery, silent ticker, commands

**Files:** Create `internal/relay/server.go`, `internal/relay/commands.go`; tests `internal/relay/server_test.go`, `internal/relay/commands_test.go`.

**Produces:**
```go
type Options struct { SilentAfter time.Duration; Version string; PublicURL string; Now func() time.Time }
type Server struct { store Store; tg Sender; opts Options; ... }   // Sender interface { Send(ctx, chatID int64, text string) error }
func NewServer(store Store, tg Sender, opts Options) *Server
func (s *Server) Handler() http.Handler   // /healthz, /v1/pair, /v1/alert, /v1/heartbeat, /v1/unpair
func (s *Server) HandleUpdate(ctx, u Update) error   // Telegram commands
func (s *Server) CheckSilent(ctx) error              // one tick of the node_silent scan
func (s *Server) RunSilentTicker(ctx, every time.Duration)
func NewCode() string  // 8 chars from "ABCDEFGHJKLMNPQRSTUVWXYZ23456789"
func FormatMessage(node Node, a alertproto.AlertRequest) string  // emoji + name + title, detail, host + time
```
Auth middleware: load node by header id, verify signature over body with `alertproto.Verify`, 401 on any failure, update `LastSeen` on success. Rate limits: token bucket per node (60/min) and per source IP for pair (10/min); per-chat 20 msgs/min with a coalesced "N alerts suppressed" message once per minute.

Delivery (`deliver(node, req)`): `info` → always send. Otherwise compare with `LastSent`: different state → send and record; same state `firing` and >= 10m since last → send and record; else drop. Muted (alert or all) → record state but do not send.

Commands: `/start` → code + instructions; `/nodes` → list with age of last_seen, silent/blocked flags, summary; `/unpair <name>`; `/mute <name> <alert|all> [duration]` (default 24h, Go duration or `1d`/`2h`); `/unmute <name> <alert|all>`; `/help`; unknown → help. Names resolved within the sending chat only.

`CheckSilent`: for `SilentCandidates(now - SilentAfter)` send `node_silent` (critical) and set `Silent`; on any authenticated request from a silent node send `node_silent_ok` and clear.

- [ ] Tests: pair flow (start→code→pair→node exists, code reuse fails, duplicate name fails, expired code fails); alert with bad signature 401; alert delivery matrix (firing new, firing repeat within 10m dropped, repeat after 10m sent, ok after firing sent, ok when never fired dropped, muted dropped but recorded, info always); heartbeat updates summary; silent ticker fires once then ok on heartbeat; chat isolation (node A's alert never goes to chat B); commands parse and act; rate limit returns 429.
- [ ] Implement.
- [ ] Test + lint; commit "Add relay server, delivery rules and Telegram commands".
